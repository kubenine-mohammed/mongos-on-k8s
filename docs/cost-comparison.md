# Cost Comparison: Atlas vs Self-Hosted (Percona on EKS)

**Important caveat up front:** we don't yet have the customer's actual Atlas invoice or cluster configuration. The numbers below use Atlas's public list pricing for a comparable dedicated, sharded cluster, plus AWS public list pricing for the self-hosted equivalent. Treat this as a *credible range*, not a quote. The single highest-value next step is getting the real Atlas bill (see [open questions](risks-and-open-questions.md)) so we can tighten this to actual numbers.

All figures generated by [`cost_model.py`](cost_model.py) — rerun it any time with updated assumptions.

## Scenario A: ~2 TB, 2 shards

| | Atlas (M60, 2 shards) | Self-hosted (EKS, 2 shards, 1yr commitment) |
|---|---|---|
| Compute | $17,301/mo | $2,213/mo (incl. storage) |
| Config servers | embedded (no extra cost at 2 shards) | $421/mo |
| mongos / monitoring | included | $199/mo |
| EKS + networking | n/a | $373/mo |
| Backup storage | $1,038/mo | $18/mo |
| **Infra total** | **$18,339/mo** ($220k/yr) | **$3,225/mo** ($39k/yr) |
| + Ops overhead (0.5 FTE SRE) | included in Atlas price | +$6,000/mo |
| **Total incl. ops** | **$18,339/mo** | **$9,225/mo** ($111k/yr) |

- Infra-only savings: **~82%**
- Realistic savings once you account for the engineering time to run it yourself: **~50%**

## Scenario B: ~5 TB, 4 shards

| | Atlas (M60, 4 shards) | Self-hosted (EKS, 4 shards, 1yr commitment) |
|---|---|---|
| Compute | $34,602/mo | $4,715/mo (incl. storage) |
| Config servers | $766/mo (dedicated, required above 3 shards) | $421/mo |
| mongos / monitoring | included | $199/mo |
| EKS + networking | n/a | $373/mo |
| Backup storage | $2,122/mo | $46/mo |
| **Infra total** | **$37,491/mo** ($450k/yr) | **$5,754/mo** ($69k/yr) |
| + Ops overhead (0.5 FTE SRE) | included in Atlas price | +$6,000/mo |
| **Total incl. ops** | **$37,491/mo** | **$11,754/mo** ($141k/yr) |

- Infra-only savings: **~85%**
- Realistic savings incl. ops overhead: **~69%**

## Why the gap is so large

- Atlas bills a large multiplier on top of raw compute for automation, managed backups, and support — that's the value they sell. At 2-5 TB scale with multiple shards, that multiplier compounds across every node.
- Self-hosting on EC2 with 1-year reserved pricing is dramatically cheaper per vCPU/GB than Atlas's per-node rate, even before counting Atlas's separate backup and config-server charges.
- The one cost Atlas *does* absorb that we have to price in ourselves is operational time — someone has to run upgrades, watch backups, and handle incidents. We've included a conservative 0.5 FTE line item so the comparison isn't misleading.

## What would change these numbers

- **Real Atlas invoice** — if the customer's actual tier/discount is different from list-price M60, the Atlas side moves accordingly (could be higher or lower).
- **Reserved Instance / Savings Plan commitment length** — a 3-year commitment drops the self-hosted compute cost further (see `RESERVED_DISCOUNT` in the script).
- **Actual data growth rate** — more shards means more nodes on both sides, but the *ratio* between Atlas and self-hosted stays roughly the same.
- **Whether we take a Percona commercial support subscription** — optional, and worth pricing in in discussions if the customer wants a vendor to call for the database layer itself (not currently included above).
- **Managed operations** — if KubeNine operates the cluster as a service rather than the customer's own team absorbing the 0.5 FTE, that becomes a services line item instead of a headcount cost, which changes how the "savings" story is told to the customer's finance team.
